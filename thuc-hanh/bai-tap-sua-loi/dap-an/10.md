# Đề số 10: Mọi thứ khỏe nhưng vẫn lỗi

## Gợi ý 1
Cả 3 container chạy, web còn báo `healthy`, nhưng trình duyệt nhận lỗi từ nginx (502). Hãy đọc log của nginx xem nó nói gì khi gọi web.

## Gợi ý 2
Healthcheck của web chạy **bên trong** container web (gọi `localhost`). Nginx thì gọi **từ container khác**. Hai đường đi này khác nhau. Ứng dụng đang lắng nghe trên địa chỉ nào?

## Gợi ý 3
Xem lệnh `CMD` trong `ung-dung/Dockerfile`, phần `--bind`. Địa chỉ `127.0.0.1` chỉ nhận kết nối từ chính nó.

## Đáp án
**Nguyên nhân:** gunicorn bị đặt `--bind 127.0.0.1:8000`, tức chỉ lắng nghe trên địa chỉ nội bộ của chính container. Healthcheck chạy bên trong container nên vẫn gọi được (healthy), nhưng nginx là container khác, kết nối từ ngoài vào bị từ chối, nên trả lỗi 502.

**Cách phát hiện:**
```sh
docker compose logs nginx                  # connect() failed (111: Connection refused) while connecting to upstream
docker compose exec nginx wget -qO- http://web:8000/health   # từ nginx: bị từ chối
docker compose exec web python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/health').status)"   # từ bên trong web: OK
```

**Cách sửa:** sửa `CMD` thành `"--bind", "0.0.0.0:8000"`, rồi build lại vì đã đổi Dockerfile: `docker compose up -d --build`.

**Bài học:** `127.0.0.1` nghĩa là "chỉ chính tôi", `0.0.0.0` nghĩa là "mọi nơi". Trong container, ứng dụng muốn nhận kết nối từ ngoài phải bind `0.0.0.0`. Và *healthy* chưa chắc là *có thể truy cập được*.
